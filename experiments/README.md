# Эксперимент: горизонтальное масштабирование

## Цель

Проверить гипотезу: пропускная способность распределённой системы растёт
пропорционально числу реплик stateless-сервиса до точки, в которой узким
местом становится общий разделяемый ресурс (PostgreSQL).

Эта точка соответствует **закону Амдала** — ускорение системы ограничено
долей того, что нельзя распараллелить.

## Архитектура стенда

```
k6 -> gateway -> nginx (балансировщик) -> [post-service × N] -> postgres + redis
```

- **gateway** — точка входа с механизмами устойчивости
- **nginx** — балансировщик нагрузки с алгоритмом least_conn
- **post-service × N** — реплики, варьируется N ∈ {1, 2, 3, 5, 7, 10}
- **postgres** — единая БД (общий ресурс, потенциальное узкое место)
- **redis** — единый кеш (общий ресурс)

## Запуск

### Автоматический прогон всей серии

```bash
chmod +x experiments/scale-experiment.sh
./experiments/scale-experiment.sh
```

Скрипт прогонит k6 с N = 1, 2, 3, 5, 7, 10 репликами и соберёт результаты
в `results/scale-experiment-<timestamp>/summary.csv`.

### Ручной прогон одной конфигурации

```bash
# 1. Поднимаем стенд с 5 репликами
docker compose up -d --scale post-service=5

# 2. Ждём готовности (~30 секунд)

# 3. Запускаем нагрузочный тест
docker compose run --rm -e TARGET=cursor -e MODE=stress k6

# 4. Смотрим результаты
cat summary.json
```

## Ожидаемые результаты

| Реплик | RPS (ожид.) | Комментарий |
|---|---|---|
| 1 | ~100 | Baseline, один процесс — узкое место |
| 2 | ~190 | Почти линейный рост |
| 3 | ~270 | Близко к линейному |
| 5 | ~400 | Замедление роста |
| 7 | ~450 | Приближение к плато |
| 10 | ~470 | Плато — БД исчерпана |

Точные числа зависят от мощности машины — но **форма кривой** должна
быть характерной (логарифмическая, не линейная).

## Что показывают результаты на защите

1. **График RPS vs N** — наглядная демонстрация эффекта масштабирования
2. **Точка перегиба** — позволяет численно определить, когда дальнейшее
   масштабирование становится неэффективным
3. **Закон Амдала** — академически корректное объяснение формы кривой
4. **Latency p95 vs N** — побочный эффект: latency сначала падает, потом
   растёт (БД захлёбывается)

## Узкие места и как их преодолеть (для будущей работы)

| Узкое место | Решение |
|---|---|
| PostgreSQL max_connections | PgBouncer как connection pooler |
| PostgreSQL CPU | Read replica для разделения чтения/записи |
| Redis (один экземпляр) | Redis Cluster или Redis Sentinel |
| Сеть nginx ↔ реплики | Несколько экземпляров nginx + DNS round-robin |

В рамках данной работы исследуется только первое масштабирование
post-service — остальные направления упоминаются как зона дальнейших исследований.
